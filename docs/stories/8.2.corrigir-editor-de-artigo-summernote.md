# Story 8.2: Corrigir editor de artigo do admin (Summernote)

## Story

- **Como:** Admin Master que escreve artigos no blog.
- **Quero:** um editor WYSIWYG funcional, responsivo e sem bugs no painel admin.
- **Para que:** editar texto seja possível e agradável, sem listeners acumulados quebrando a digitação.

## Contexto

O "Estúdio do Artigo" no admin usa Summernote WYSIWYG, mas a implementação apresenta bugs críticos:

1. **Listeners duplicados:** `showBlogForm()` registra um novo listener `summernote.change` toda vez que o formulário abre, acumulando N ouvintes. Após abrir 3 vezes, uma tecla dispara o callback 3 vezes.
2. **Sem `destroy()`:** o Summernote nunca é destruído antes de reinicializar. Trocar de aba quebra o DOM.
3. **CSS insuficiente:** área de texto 360px (apertada), placeholder invisível no tema escuro, dropdowns sem tema dark próprio.
4. **Toolbar limitada:** sem headings (H1-H3), sem alinhamento, sem tachado — essenciais para artigos.
5. **Código confuso:** `quillEditorInstance` mas é Summernote — nome enganoso.

## Acceptance Criteria

1. `showBlogForm()` não acumula listeners duplicados do Summernote.
2. O editor é destruído e reinicializado corretamente a cada abertura do formulário.
3. A área editável tem `min-height: 500px` e placeholder visível.
4. Dropdowns internos do Summernote (style, fontname, color) funcionam com tema escuro.
5. Toolbar inclui H1, H2, H3, alinhamento e tachado.
6. Alternar entre modo Visual e HTML funciona sem erros e sem listeners duplicados.
7. Nome da instância é `summernoteEditor` (não `quillEditorInstance`).
8. Versão do projeto bumpada nos 3 lugares.

## Technical Contract

| Alteração | Onde |
| --- | --- |
| Init/destroy do editor | `showBlogForm()`, nova função `destroyBlogEditor()` |
| Listeners | mover `summernote.change` para IIFE, executar só 1x |
| CSS Summernote | bloco `<style>` em `admin.html` |
| Toolbar | config `toolbar` no `summernote()` |
| Renomear instância | todas as referências a `quillEditorInstance` |

## Causa raiz adicional descoberta

Os arquivos `summernote-lite.min.css` e `summernote-lite.min.js` **não existiam** em `src/assets/vendor/summernote/`. O editor nunca carregou — era impossível editar texto porque o WYSIWYG simplesmente não inicializava.

**Correção:** baixados Summernote 0.8.20 do CDN para `src/assets/vendor/summernote/` e importações movidas para `index.html` (vendor deferred), garantindo carregamento antes da página admin.
