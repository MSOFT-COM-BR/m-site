# Story 5.1: Instalacao real de apps gratuitos

## Story

- **Como:** usuario autenticado do Miranda Soft.
- **Quero:** que usar uma ferramenta gratuita em `/apps` registre esse app na minha conta de verdade.
- **Para que:** o app instalado apareca em "Meus Aplicativos" no `/premium` e em qualquer outro lugar que leia meus apps, sem depender do navegador que usei.

## Contexto

Hoje `apps.html` roda uma animacao falsa de instalacao (`runInstallEffect`, com textos como "Verificando licenca...", "Baixando recursos...") e ao final chama `AppState.install(appId)`, que so grava em `localStorage` (`msoft_installed_apps`). A funcao `syncWithApi()` que deveria persistir isso no backend existe mas so faz `console.log` — nunca chama a API. O backend (`m-manage`) ja tem o endpoint `POST /apps/install` pronto e funcional (grava em `mApps`, com indice unico `userId+appKey`), mas nada no frontend o chama. Resultado: o dashboard `/premium`, que le `GET /apps` (dado real do Mongo), nunca ve os apps gratuitos "instalados" pelo usuario.

## Acceptance Criteria

1. Ao clicar num app gratuito em `/apps` estando autenticado, o frontend chama `POST /apps/install` com `{ name, appKey }` e so marca como instalado (localStorage/UI) apos resposta `success: true`.
2. Se a chamada falhar, a UI mostra erro e nao marca o app como instalado.
3. Usuario nao autenticado pode usar as ferramentas gratuitas normalmente (uso anonimo), mas ve um CTA para logar/cadastrar e persistir o app na conta — instalacao real exige sessao.
4. O app instalado passa a aparecer em `/premium` na secao "Meus Aplicativos" (`GET /apps` ja retorna, sem mudanca de contrato).
5. Clicar em instalar um app ja instalado (endpoint e idempotente via `findOne` antes do insert) nao gera duplicidade nem erro.
6. A animacao de progresso pode ser mantida como feedback visual, mas so avanca para "Concluido" apos confirmacao real do backend (nao mais tempo fixo simulado desacoplado da chamada).

## Validation

- `node -e "new Function(script)"` sobre o `<script>` inline de `apps.html`: sintaxe valida.
- `AppState.install` extraido e executado isoladamente em Node com `fetchAPI`/`authService` mockados:
  - usuario logado → chama `POST /apps/install` com `{ name, appKey }` correto, marca instalado so apos sucesso.
  - segunda chamada no mesmo app → nao rechama a API (ja instalado localmente).
  - usuario deslogado → retorna `false`, nao chama a API.
- Backend real (`m-manage`) rodado localmente contra MongoDB descartavel (`mongo:7.0` em container temporario, removido apos o teste):
  - `POST /auth/register` cria usuario de teste.
  - `POST /apps/install` com `appKey: json-formatter` grava em `mApps` e retorna `success: true`.
  - `GET /apps` com o token do usuario retorna o app instalado — exatamente o payload que `premium.html` consome.
  - Segunda chamada a `POST /apps/install` com o mesmo `appKey` retorna `"App already installed"` sem duplicar (`GET /apps` continua com 1 item).
  - `POST /apps/install` sem `Authorization` retorna `{ success: false, error: 'Não autorizado' }`.
- Nenhum container/processo de teste deixado rodando apos a validacao.
