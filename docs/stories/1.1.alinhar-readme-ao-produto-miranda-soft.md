## Story

- **Como:** contribuidor ou operador tecnico do m-site.
- **Quero:** que o README descreva com precisao o produto Miranda Soft e seu fluxo atual de execucao e deploy.
- **Para que:** eu consiga operar, manter e publicar o site sem seguir instrucoes ou referencias legadas.

## Context

O PRD define o produto como o site institucional e vitrine digital da Miranda Soft. O runtime atual ja usa essa marca em `index.html`, `src/config/config.js`, paginas e footer. Em contraste, o `README.md` ainda apresenta uma landing pessoal de Breno Miranda, aponta para o dominio legado e sugere iniciar o site na porta `3000`, que e reservada para a API local.

Esta e a primeira historia do `EPIC-1`. Ela nao deve alterar o comportamento do site, da API ou das paginas existentes.

## Acceptance Criteria

1. O `README.md` identifica o repositorio como o m-site institucional e vitrine digital da Miranda Soft, sem referencias a Breno Miranda, `brenossan.com.br` ou a landing pessoal legada.
2. A documentacao descreve apenas a stack confirmada: SPA em JavaScript vanilla, HTML/CSS, componentes HTML carregados dinamicamente, assets estaticos e integracao com API backend.
3. O guia local deixa explicito que a API local usa `http://localhost:3000` e que o servidor do site deve usar outra porta, com um comando funcional para servi-lo estaticamente.
4. O README documenta a configuracao de API confirmada em `src/config/config.js`, incluindo producao, localhost e o override `window.__MSOFT_API_BASE__`, sem revelar ou adicionar segredos.
5. O README descreve as areas e rotas principais do produto de acordo com o PRD e `config.routes.validPages`, incluindo as paginas publicas, blog, marketplace, healthtech e areas de conta quando aplicavel.
6. As orientacoes de deploy refletem um site estatico, o `Dockerfile`, `serve.json` e a necessidade de fallback para `index.html` nas rotas SPA.
7. A mudanca e apenas documental: nenhum arquivo de runtime, configuracao de API ou pagina do site e modificado por esta historia.
