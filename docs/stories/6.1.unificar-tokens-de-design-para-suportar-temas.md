# Story 6.1: Unificar tokens de design para suportar temas claro e escuro

## Story

- **Como:** desenvolvedor mantendo o design system do Miranda Soft.
- **Quero:** um unico conjunto de CSS custom properties, escopado por `[data-bs-theme]`, com variante clara e escura.
- **Para que:** o toggle de tema (story 6.2) tenha em que se apoiar, sem duas fontes de verdade divergentes nem paginas que ignoram o tema.

## Contexto

Hoje o m-site e 100% dark-only:
- `index.html:52` fixa `<body data-bs-theme="dark">` sem alternativa.
- `src/assets/css/design-system.css:25` e `src/assets/css/developer.css:10` tem cada um seu proprio bloco `:root` com tokens `--ms-*` quase identicos (mesmos nomes, mesmos valores hex tipo `--ms-surface: #0a0a0f`) — duas fontes da mesma verdade, ja duplicadas sem tema nenhum.
- `developer.css:47` usa o seletor `body[data-bs-theme="dark"]` para aplicar `--ms-surface`/`--ms-text-primary`, mas nao existe nenhum `body[data-bs-theme="light"]` correspondente.
- Paginas individuais (`premium.html`, `marketplace.html`, `apps.html` e outras) usam classes utilitarias do Bootstrap fixas (`bg-dark`, `text-white`, `bg-black`) e cores inline (`rgba(255,255,255,...)`, `background: transparent !important`) em vez de tokens — essas nao reagem a troca de `data-bs-theme` de jeito nenhum.

Levantamento do padrao usado no m-notas (`app/Views/layout.php`), que ja tem tema funcional, confirma a abordagem CSS custom properties + `[data-bs-theme]` como a mais simples de importar para uma stack Bootstrap 5 como a do m-site.

## Acceptance Criteria

1. Existe um unico arquivo/bloco de tokens `--ms-*` (elimina a duplicacao entre `design-system.css` e `developer.css`); os dois arquivos passam a importar/referenciar a mesma fonte.
2. Os tokens de cor (`--ms-surface*`, `--ms-text-*`, `--ms-outline*`, `--ms-on-*`) tem valor definido tanto para `[data-bs-theme="dark"]` quanto para `[data-bs-theme="light"]`. Tokens de marca (`--ms-primary`, `--ms-secondary`, `--ms-tertiary`) podem manter o mesmo valor nos dois temas se a marca nao mudar de matiz — o objetivo e legibilidade/contraste, nao trocar a identidade visual.
3. Um levantamento (nao precisa ser 100% de cobertura nesta story) identifica quais paginas usam classes/cores hardcoded que vazam o tema dark (`bg-dark`, `text-white`, `bg-black`, `rgba(255,255,255,...)` fixo) — documentado como lista de arquivos para a story 6.2 ou uma story de acompanhamento tratar.
4. As paginas principais do fluxo logado (`premium.html`, `marketplace.html`, `apps.html`, `my-apps.html`) sao migradas para usar os tokens `--ms-*` em vez de classes Bootstrap dark-only, nos elementos que hoje tem `style="background: ... !important"` inline (os cards "transparentes" com borda hardcoded encontrados em `premium.html`).
5. Nenhuma regressao visual no tema escuro: a aparencia atual (dark) e o resultado de `[data-bs-theme="dark"]` usando os mesmos valores hex que existem hoje.

## Technical Notes

- Modelo de referencia: `m-notas/public/assets/css/dark-theme.css:9-47`, que redefine tokens Bootstrap (`--bs-body-bg`, `--bs-body-color`) dentro de `[data-bs-theme='dark']` — no m-site o equivalente e escopar os tokens `--ms-*` (e os Bootstrap nativos usados) dentro de `[data-bs-theme='dark']` e `[data-bs-theme='light']`.
- Nao criar um sistema de temas novo do zero — reaproveitar a convencao `data-bs-theme` ja usada em `index.html:52` (e ja e a convencao nativa do Bootstrap 5.3, que o projeto ja usa).

## Tasks

- [ ] Tokens de superficie/texto/outline com valor para os dois temas.
- [ ] Paginas do fluxo logado nao dependem de `bg-dark`/`text-white`/cores inline fixas para os elementos migrados.
- [ ] Tema escuro visualmente identico ao atual.
