# Story 7.4: Remover aplicação HealthTech do m-site

## Story

- **Como:** Admin Master da Miranda Soft.
- **Quero:** que a aplicação HealthTech seja completamente removida do site institucional (m-site).
- **Para que:** não exista nenhuma página, serviço, rota ou referência pública acessível a usuários anônimos ou logados no domínio público do site.

## Contexto

A story 7.3 já corrigiu o backend (`m-manage`) para exigir `requireAppAccess('healthtech_os_v1')` e removeu o link público de `/ecossistema`. No entanto, a aplicação HealthTech continua existindo no frontend do m-site:

- As rotas `healthtech-dashboard`, `healthtech-patients` e `healthtech-formulas` ainda estão registradas em `validPages` e podem ser acessadas diretamente por URL.
- As páginas HTML parciais continuam em `src/pages/`.
- O serviço `HealthTechService` continua sendo carregado globalmente via `index.html`.
- Há referências residuais em `core.js`, `premium.html`, README e PRD.

Mesmo que o backend agora negue os dados, a presença do frontend cria uma superfície de ataque desnecessária, confusão de UX e dívida técnica. A remoção completa elimina o risco de URL conhecida, dependências mortas e conteúdo desatualizado.

## Acceptance Criteria

1. `src/config/config.js` não contém mais `healthtech-dashboard`, `healthtech-patients` nem `healthtech-formulas` em `validPages`.
2. Os arquivos `src/pages/healthtech-dashboard.html`, `src/pages/healthtech-patients.html` e `src/pages/healthtech-formulas.html` são removidos.
3. `src/services/healthtech-service.js` é removido e não é mais importado em `index.html`.
4. `src/core/core.js` não trata mais `healthtech-dashboard` em `isLoggedArea` nem em `hideMainFrame`.
5. `src/pages/premium.html` não contém mais o card/override `healthtech_os_v1` nem a função `openDashboard()`.
6. `README.md` e `docs/PRD/m-site.md` não listam mais HealthTech como área/rotas do site.
7. `docs/stories/2.1.criar-portal-do-ecossistema-miranda-soft.md` não apresenta HealthTech como destino existente do ecossistema.
8. A versão do projeto é atualizada em `src/config/config.js`, no comentário `<!-- Version: VX.Y.Z -->` de `index.html` e nas query strings `?v=X.Y.Z` dos scripts críticos em `index.html`.
9. Acessar `/healthtech-dashboard` (ou patients/formulas) no site servido localmente retorna 404 e não carrega conteúdo da aplicação.

## Technical Contract

| Removido | Onde |
| --- | --- |
| Rotas `healthtech-*` | `src/config/config.js` (`validPages`) |
| Páginas parciais | `src/pages/healthtech-dashboard.html`, `healthtech-patients.html`, `healthtech-formulas.html` |
| Cliente da API | `src/services/healthtech-service.js` |
| Import do cliente | `index.html` |
| Tratamento especial de frame | `src/core/core.js` (`isLoggedArea`, `hideMainFrame`) |
| Override do app no premium | `src/pages/premium.html` (`APP_OVERRIDES`) |

## Riscos / Fora do escopo

- Esta story não altera o backend `m-manage`; a proteção por `requireAppAccess` continua válida via story 7.3.
- Não migramos dados, pois o frontend do site não armazena dados de pacientes; os dados continuam no backend protegido.
- Se futuramente o HealthTech voltar ao site, será uma nova feature com design de segurança por padrão.
